# Правила работы с Espada

1. Единственное рабочее приложение находится в корне этого проекта. Сначала
   прочитайте README.md, docs/CURRENT_APP.md, РЕСЕТЫ/versions.json и git status.
2. Проверенная публикация на 24.10.2026 — c61a513 из ветки
   codex/unified-local-20261023. Удалённая main старее. Более поздний релиз
   подтверждайте успешным развёртыванием GitHub Pages, не названием ветки.
3. АРХИВ — исторические материалы, не текущие исходники и не требования.
   Не используйте его README, планы, макеты и скриншоты как описание текущего
   интерфейса. Не восстанавливайте архив без задачи на восстановление.
4. Перед проверкой кабинета определите фактические actor.role, режим
   подключения и ширину экрана. Три вкладки «Прогресс / Домашняя работа /
   Связь с учителем» принадлежат parent. Не показывайте teacher вместо parent.
   Если ожидание расходится с реализацией, сообщите конкретное расхождение
   до изменения поведения; не выдавайте другой кабинет за готовый результат.
5. src/arena и преподавательские разделы подключены в опубликованном релизе.
   Старое название не делает код мусором. Изменение подключённых функций —
   отдельная задача изменения продукта, а не уборка файлов.
6. Черновики, скриншоты, отчёты и временные копии храните только в АРХИВ
   с понятными именами. Не создавайте рядом второе приложение, design-lab,
   review или альтернативную инструкцию текущей версии.
7. Точки восстановления — в РЕСЕТЫ/versions.json. Не передвигайте текущую
   и предыдущую опубликованные точки без нового успешного развёртывания.
   Не выполняйте ресет при обычном чтении или диагностике.
8. Не включайте архив в сборку, проверку типов и публикацию. Сохраняйте
   лицензии ресурсов. Уборку проверяйте npm run check и веб-сборкой.
