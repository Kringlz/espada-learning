# Уроки, база и тесты

Новый модуль использует PostgreSQL через существующий клиент Supabase и существующий вход по email/паролю. Миграция: `supabase/migrations/006_persistent_lessons.sql`. Данные прежних тем, групп, домашних заданий и результатов учителя сохранены. Новые результаты находятся в **Учёба → Уроки и тесты → Мои попытки**; они не меняют автоматически оценки учителя или прежний расчёт освоения тем.

## Где посмотреть сейчас

В подготовленном локальном предпросмотре: `http://127.0.0.1:8087/` → **Учёба → Уроки и тесты**. Он доступен, пока работают локальные серверы. Три урока: «Порядок действий», «Линейные уравнения», «Отношения и пропорции». У каждого 20 вопросов: 8 простых, 8 средних и 4 сложных. Все материалы помечены как демонстрационные, без выдуманных видео и учебников.

Для редактора переключитесь на **Анна Белова** → **Программа → Уроки и тесты**. Можно создать урок, изменить его конспект, тему, порядок, источники, видео, вопросы, ответы и проходной балл; посмотреть предпросмотр; проверить изменения и сохранить черновик или публикацию. Изменения формы до сохранения не переживают закрытие страницы.

На публичном сайте база Supabase пока не подключена. Без настройки новый модуль показывает сообщение об отсутствии подключения и не подменяет базу браузерными данными. Локальный предпросмотр — отдельная тестовая PostgreSQL с тестовыми аккаунтами, **не проверка размещённого Supabase Auth или PostgREST**.

## Подключение настоящего Supabase

1. Создать проект Supabase. Не отправлять пароль базы или secret/service-role key в чат и не добавлять их в приложение.
2. Применить миграции `001`–`006` по порядку (на существующей базе — только ещё не применённые), затем `supabase/seed.sql` с программой и старыми шаблонами. Миграция 006 выполняется транзакционно. **Не применять `supabase/tests/*` к настоящему проекту.**
3. Через Supabase Auth создать пользователей; отключить свободную регистрацию. Создать профиль первого администратора с UUID из Auth:

   ```sql
   insert into public.profiles(id, name, role, active)
   values ('ЗАМЕНИТЕ-НА-UUID-ИЗ-AUTH', 'Администратор', 'admin', true);
   ```

   Остальные профили и группы управляются существующим административным экраном. UUID каждого профиля должен соответствовать пользователю Auth. Ученику нужен активный профиль с ролью `student`.
4. Указать в локальном `.env` или в окружении сборки:

   ```dotenv
   EXPO_PUBLIC_DATA_MODE=supabase
   EXPO_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLIC_PUBLISHABLE_KEY
   APP_ENV=production
   ```

   Это публичные настройки клиента. Серверных секретов в приложении нет. Убрать `EXPO_PUBLIC_LESSON_PREVIEW_URL` из окружения настоящей сборки.
5. Пересобрать приложение, войти как администратор, импортировать материалы с проверкой и сохранением. Для показа ученикам явно выбрать публикацию. Пример из репозитория по умолчанию содержит **черновики**; автоматически в настоящую базу он не загружается.
6. Проверить вход, RLS через реальный API, импорт, тест и восстановление на двух настоящих аккаунтах Supabase. Локальные проверки не заменяют этот шаг.
7. Для GitHub Pages будущая сборка должна получать эти три публичные переменные вместо текущего `EXPO_PUBLIC_DATA_MODE: demo` в workflow. Публикация — отдельное действие после настройки и разрешения владельца. Текущие изменения не развёрнуты на публичном сайте.

## Подготовка будущих уроков

Образец: [`content/demo-lessons.json`](../content/demo-lessons.json). Документ JSON должен иметь `schemaVersion: 1`, массивы `courses`, `sections`, `lessons`. У курса: `id`, `title`, целый `order`. У раздела дополнительно `courseId`. Курсы/разделы, уже находящиеся в базе, можно не включать в пакет.

У урока:

- `id`: постоянный идентификатор, например `math-fractions-01`; `sectionId`: существующий или импортируемый раздел; `topicId`: ID из текущей программы (`public.topics`, также `src/data/curriculum.ts`).
- `title`, целый `order`, `summary`: непустой массив блоков `{ "kind": "paragraph", "text": "..." }`. Виды: `heading`, `paragraph`, `example`, `list`. Это текстовые блоки, не HTML; в списке строки разделяются `\n`.
- `videoUrl`: ваша HTTPS-ссылка или `null`. MP4/WebM/HLS-ссылка воспроизводится встроенным плеером при поддержке формата браузером/устройством; ссылка на страницу видеосервиса открывается отдельно. Существующая загрузка видео по темам продолжает работать в дереве тем.
- `sources`: массив `{ "title": "Название и сведения об источнике", "url": "https://..." }`; ссылка необязательна. Пустой массив допустим. Указывайте только реальные источники.
- `demo`: `false` для настоящих уроков; `status`: `draft` или `published`. Отсутствующий статус означает **draft**, в том числе при повторном импорте ранее опубликованного урока.
- `test`: `{ "passScore": 7 }`. Целое от 1 до 10. **7/10 — демонстрационное значение, требующее окончательного решения.**
- `questions`: массив вопросов. Вопрос: `id`, `difficulty` (`easy`, `medium`, `hard`), `type` (`single`, `multiple`), `prompt`, `options`, `correctOptionIds`, `explanation`.
- Вариант: `{ "id": "a", "text": "..." }`. В вопросе 2–8 вариантов. Для `single` ровно один ID в `correctOptionIds`; для `multiple` — один или несколько. ID должны существовать среди вариантов, повторы запрещены.

Все ID: латинские буквы, цифры, точки, дефисы и подчёркивания; длина 1–120, первый символ — буква или цифра. ID вопросов уникальны во всём банке и не переносятся между уроками. ID вариантов уникальны внутри вопроса. Не меняйте ID при исправлении текста.

В интерфейсе: **Анна Белова / настоящий администратор → Программа → Уроки и тесты → Импорт JSON → выбрать файл или вставить текст → Проверить перед сохранением → Сохранить в базе**.

Проверка выполняется теми же серверными правилами, что и запись, но откатывает изменения. Ошибка в последнем вопросе отменяет весь пакет. Повторный импорт обновляет совпадающие ID. Пропущенные курсы, разделы, уроки, вопросы и варианты не удаляются. Для предоставленного вопроса явный набор `correctOptionIds` заменяет ключ целиком; ранее существующие варианты, не указанные как правильные, становятся неправильными. Нельзя обойти предел 8 вариантов добавлением новых ID при повторном импорте. Для редакции пользуйтесь существующими ID, не создавайте новый вариант вместо исправления старого.

Пакет — до 100 уроков; интерфейс принимает файл до 2 МБ. Для больших материалов разбивайте пакет на части. Удаление учебного контента намеренно не выполняется импортом. При необходимости временно скрыть урок снимите публикацию. Новые курсы/разделы создаются через импорт; форма урока использует существующие разделы (или создаёт начальный курс/раздел в пустой базе).

## Правила теста и сохранения

- Ровно **10 различных вопросов: 4 простых, 4 средних, 2 сложных**. Недостаточный банк нельзя опубликовать; для черновика показываются недостающие категории.
- Сервер сначала выбирает невиденные вопросы; затем — встречавшиеся реже, при равенстве — более давно; равные кандидаты и порядок теста перемешиваются. Совпадение всего набора с предыдущим предотвращается, если есть альтернативный вопрос той же сложности.
- На ученика и урок может существовать только одна незавершённая попытка. Повтор запроса начала/сдачи не создаёт дубликаты. Вопросы, варианты, ключ, объяснение, версия урока и проходной балл копируются при старте.
- Ответы сохраняются при каждом выборе. До подтверждения записи интерфейс показывает сохранение; при сбое — ошибку и повтор. Неотправленные ответы после закрытия страницы могут быть потеряны; **подтверждённые** восстанавливаются из базы. Несовместимые одновременные изменения в другой вкладке отклоняются, можно восстановить серверную версию.
- Один вопрос — один балл. Для нескольких ответов требуется точный набор без пропусков и лишних вариантов. Порядок выбора не влияет. Перед сдачей нужно ответить на все 10 вопросов.
- После сдачи результат неизменяемый. Изменение/снятие публикации урока не меняет уже начатую попытку или её историю. История доступна из «Мои попытки», даже если урок снят с публикации.
- У новых тестов нет автономного режима. Сбой базы отображается явно. Старые тренировочные мини-проверки в дереве тем сохранены как отдельная прежняя функция; их клиентский банк не используется в новых защищённых тестах.

## Серверная защита

RPC `lesson_catalog`, `lesson_read` отдают только опубликованные материалы активным ученикам/учителям. `lesson_admin_export`, `lesson_import` требуют администратора. `lesson_start`, `lesson_attempt_read`, `lesson_attempt_history`, `lesson_save_answers`, `lesson_submit` требуют ученика и проверяют владельца попытки.

Таблицы с ключами `lesson_questions`, `lesson_options`, `lesson_attempt_items` не читаются учеником даже напрямую: RLS разрешает их только администратору. Закрытые сериализаторы `lesson_public_json` и `lesson_attempt_json` не имеют разрешения EXECUTE у клиента. Ответы/объяснения отправляются только в результате собственной сданной попытки. В обычный `load_learning_state` новый банк не включён. Мутации таблиц доступны только через проверенные RPC; балл вычисляет PostgreSQL.

Импорт и создание снимка согласованы блокировкой. Сохранение/сдача блокируют строку попытки, проверяют ревизию. Удаление профиля прежним процессом erasure каскадно удаляет новые попытки и их ответы. Публикация образца с ответами в репозитории служит документацией демонстрационного материала; реальные закрытые банки не следует коммитить в публичный репозиторий.

## Воспроизводимый локальный запуск

Нужны Node, npm и PostgreSQL 17 с `psql`/`createdb` в PATH. Используйте **новую пустую локальную базу** с именем `espada_lessons_*`:

```sh
createdb espada_lessons_preview
export ESPADA_TEST_DATABASE_URL=postgresql://127.0.0.1/espada_lessons_preview
sh scripts/test-database.sh
npm run lessons:seed:local
npm run lessons:server:local
```

Во втором терминале:

```sh
npm run lessons:preview
```

Первый скрипт устанавливает тестовые Auth/Storage-обвязки, миграции и тестовые аккаунты; запускает старые и новые проверки. Второй явно публикует три демоурока **только в локальную тестовую базу**. Третий запускает мост на `127.0.0.1:55433`; это только инструмент разработки с четырьмя фиксированными идентификаторами, не настоящий вход. Он отклоняет внешние Host/Origin, другие RPC и подключение к нелокальной базе. Никогда не разворачивать этот сервер публично.

Для уже созданной в этой рабочей сессии базы: адрес `postgresql://127.0.0.1:55432/espada_lessons_test`, каталог кластера `/private/tmp/espada-pg`; `psql` находится в `/opt/homebrew/opt/postgresql@17/bin`. Не запускайте bootstrap повторно на существующей базе. После перезапуска компьютера сначала запустите PostgreSQL, затем сервер предпросмотра и Expo.

## Проверки и границы

- `npm run check`: типы, прежние тесты и проверка всех 60 демонстрационных ключей независимыми вычислениями/проверенными наборами.
- `sh scripts/test-database.sh`: все миграции с нуля, прежние SQL-права, импорт, откат, повторный импорт, ограничения ролей, восстановление, точный состав, смена вопросов, серверная оценка, неизменяемые снимки.
- `npm run test:lessons:db`: повтор только тестов нового модуля на настроенной одноразовой базе. Созданные этой проверкой строки имеют случайный префикс и удаляются после неё; пользовательские/демоуроки не затрагиваются.
- Workflow GitHub дополнен отдельной проверкой PostgreSQL 17 перед развёртыванием. Сам workflow для этих изменений ещё не запускался на GitHub.

Фактически проверено локально: миграции 001–006, SQL-права и полный цикл через PostgreSQL; браузерные экраны урока/теста/результатов, сохранение после обновления страницы, мобильная ширина 390 px. Размещённый Supabase, реальный вход Auth, API PostgREST и физические мобильные устройства пока не проверены — проекта Supabase ещё нет.
