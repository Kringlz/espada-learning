# Вход и групповая активность: проверка и выпуск

## Статус

Основано на production `ef57327`. Функции входа сохранены отдельным commit
`27323ba`; финальные UX-доработки входят в последующий commit. Новый backend
подготовлен и проверен только локально. Production-миграция и флаг лиги
пока НЕ применены. Требуются разблокированный Mac и штатный вход оператора в
существующий Supabase-проект Espada. Секреты в чат не передаются.

## Вход

- «Запомнить меня» выключен по умолчанию. SDK-токены хранятся в sessionStorage
  (на native — в памяти), при явном выборе — в localStorage (native SecureStore).
  Пароль не записывается ни в одно хранилище. Очистка охватывает оба хранилища
  и PKCE verifier; истечение и отзыв сессии обрабатывает текущий Supabase SDK.
- Восстановление вкладок зависит от браузера; на общем устройстве необходимо
  пользоваться «Выйти». При ошибке сети SDK удаляет локальную сессию; экран входа отдельно сообщает,
  что сервер не подтвердил завершение сеанса. Успешный серверный отзыв не имитируется.
- Независимые доступные кнопки показа/скрытия пароля, скрыто по умолчанию.
  autocomplete=current-password/new-password и нативные textContentType.
- Новый пароль вводится дважды и сравнивается без trim/нормализации.
  Подтверждённый аккаунт, завершающий профиль, пароль повторно не вводит.
- Повторный login блокируется и в UI, и единым выполняющимся запросом;
  регистрация защищена синхронным флагом. Переключение формы во время запроса
  заблокировано, ошибка позволяет повторить попытку.

## Доверенные данные группы

Существующие личные очки и отметки — локальные, не являются серверным
доказательством. Их нельзя импортировать как доверенный XP. Они сохраняются.
Лига учитывает задания учебника после включения: +20 за уникальный правильный
ответ, как в существующем правиле. Недельных сбросов и глобальной лиги нет.
Локальные +10 за просмотр видео остаются личными и в лигу не импортируются.

`010_group_learning.sql` добавляет каталог ключей, журнал запросов, ответы,
прочитанные страницы и уникальный XP. Сервер не принимает количество баллов
или ID другого ученика. Правильность сверяется с авторским ключом. Повтор,
потерянное подтверждение и конкурентные отправки не дают повторного XP.
Чтение — самоотметка пользователя; последняя активность учителя обозначена
именно как последний проверенный ответ. Завершённый урок требует всех разделов
и всех отправленных ответов. Существующие отметки чтения передаются вместе с
новым ответом, но старые локальные ответы/баллы не импортируются.

Новые таблицы имеют RLS и не имеют прямых разрешений для anon/authenticated.
RPC проверяет активный профиль и членство каждый раз. Учителю доступны только
назначенные группы (администратору — существующие административные права).
Ученику выдаются только имя, место, XP и isCurrent своей группы. Нет чужих email,
заметок, ответов, времени активности или доступа родителя к общей лиге.
Равные XP дают равные места, порядок стабилен по имени и ID; при 0 XP место
не присваивается. Есть пустое состояние, поиск учителя, загрузка, ошибка,
повтор и обновление при возвращении ученика во вкладку успехов.

## Порядок production-миграции

1. Проверить актуальную схему в существующем проекте `anugktopawgukdxhqvze`.
   Миграция 010 не зависит от запрета регистрации учителей из 009; отдельный
   незавершённый выпуск 009 не применять попутно без согласования.
2. В транзакции применить только `supabase/migrations/010_group_learning.sql`
   и `supabase/study-seed.sql` (55 тем, 575 авторских ключей). Никаких bootstrap,
   demo-fixtures, тестов или локального seed пользователей на production.
3. Проверить определения RPC/разрешения и наличие каталога, без создания или
   изменения реальных учеников для QA. Авторизованные сценарии предварительно
   проверены на локальных синтетических профилях.
4. После UI-проверки выпустить клиент через существующий GitHub Pages из main.
   Затем включить репозиторную переменную `EXPO_PUBLIC_GROUP_LEAGUE_ENABLED=true`
   и повторить существующий workflow. Пока false/отсутствует, новая панель и
   новые записи выключены; прежние уроки и очки работают как раньше.
5. Проверить успешный CI/deploy и соответствие live-бандла итоговому commit.

Старый клиент не использует новые таблицы/RPC и совместим со схемой. Миграция
ничего не удаляет, не меняет старые профили, оценки, роли, RLS или секреты.
Для отката выключить флаг и выпустить предыдущий клиент. Новые записи оставить
для последующего восстановления; не удалять журнал и не обнулять XP.

## Проверки и оставшиеся ограничения

`npm run check`: TypeScript и 127 тестов проходят. `git diff --check` и форматирование проходят.
Demo-export с включённой лигой и production Pages-export с выключенной лигой собираются.

Локальные автоматические проверки охватывают реальный auth SDK с подставленным
HTTP: remember on/off, reload/reopen модели хранилища, logout, ошибку входа,
отозванный/истёкший token, точность пароля, совпадение и двойную отправку.
Также проверяются поздние/ошибочные ответы группы, отсутствие устаревших строк,
равные места, пустая группа, правильность начисления и завершения урока.

Полный SQL-suite выполняется только в новой одноразовой базе. Дополнительно
проверяются teacher/student/parent/anon, другая группа, прямые таблицы и helper,
6 конкурентных повторов одного requestId, разные requestId для того же задания,
неверный ответ, изменение запроса, неподдерживаемые задания/страницы, обновление
рейтинга, деактивированный ученик и точные поля ответа ученика.

Визуальный QA desktop/mobile, реальные browser autofill/reopen, production RPC
и live-проверка нового выпуска пока заблокированы отсутствием штатного доступа.
Не считать эти пункты выполненными и не включать production-лигу до проверки.
