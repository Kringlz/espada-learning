## Изменения

- Компактные отдельные формы входа, регистрации и восстановления в космической палитре с зелёными акцентами. Вход: почта, пароль, «Запомнить меня», «Войти», «Забыли пароль?». Роль берётся из серверного профиля.
- Повтор пароля при регистрации и установке нового пароля. Точное сравнение, без обрезки пробелов и Unicode-нормализации. Ошибка «Пароли не совпадают» появляется после ухода из заполненного повтора или отправки, исчезает при исправлении. Прежний минимум — 8 символов; дополнительные серверные ограничения остаются за Supabase.
- Показ/скрытие, `new-password`/`current-password`, нативные подсказки автозаполнения, настоящий HTML form на web, переходы с клавиатуры и отправка Enter. Вставка разрешена. Пароль остаётся только в памяти формы до её смены/закрытия, повтор никогда не передаётся сервису. Ошибка запроса сохраняет введённые значения для повтора.
- Синхронная блокировка повторной отправки. Нейтральные ошибки неправильных учётных данных, существующего аккаунта и запросов восстановления.
- Регистрация по-прежнему доступна только ученику и родителю, с прежним кодом группы/ученика. Прежнее подтверждение почты кодом `signup` сохранено; серверные политики не менялись.
- Восстановление, отсутствовавшее в интерфейсе, использует `resetPasswordForEmail`, событие `PASSWORD_RECOVERY`, `verifyOtp(type: recovery)` (когда письмо содержит код) и `updateUser`. Ссылка обрабатывается штатным web SDK, нативный обработчик принимает только `espada://auth/recovery`. После изменения — выход и обычный вход с новым паролем. Режим восстановления сохраняется при перезагрузке до завершения/отмены.
- Сетевой сбой загрузки кабинета предлагает повторить загрузку. Форма завершения регистрации доступна лишь после проверки отсутствия своего профиля; действующему пользователю не предлагают выбрать роль повторно.
- Ответы старых запросов после смены сессии не могут вернуть старый интерфейс. Очередь учебных изменений привязана к владельцу, перед отправкой сверяется текущий аккаунт. Профили, курс и локальные заметки остаются разделены по ID.

## «Запомнить меня» и выход

| Платформа | Включено | Выключено | Степень проверки |
| --- | --- | --- | --- |
| Web, Chrome | Токены Supabase в `localStorage`; восстановление в новой вкладке/контексте, пока сервер допускает сессию | Токены в `sessionStorage`; перезагрузка той же вкладки сохраняет вход, новая независимая вкладка требует вход | Реальная web-сборка, синтетические HTTP-ответы; перезагрузка, новые вкладки, новый браузерный контекст с перенесённым постоянным хранилищем |
| Нативные iOS/Android | Существующее разбитое на части хранилище Expo SecureStore | Только память процесса; сворачивание приложения само по себе не завершает процесс | Успешный экспорт обеих платформ; модульные проверки адаптеров. На устройствах не запускалось |

Закрытие окна не является гарантией выхода: браузер может восстановить `sessionStorage` при восстановлении сеанса или дублировании вкладки. Закрытие и повторный запуск самого приложения Chrome с его конкретными настройками восстановления не проверялись. Очистка данных браузера, правила сервера, отзыв refresh token и сроки сессии могут прекратить сохранённый вход.

Переключение на временный режим удаляет постоянные токены, включая вспомогательные ключи. Пустое исходное хранилище не восстанавливает старую сессию из целевого. Миграция и обновления SDK последовательно обрабатываются адаптером; сбой записи настройки не уничтожает исходную сессию. Пароли в хранилища не записываются. Автоматическое обновление токенов остаётся включённым; нативный цикл приостанавливается только в фоне и возобновляется при активации, web управляется SDK.

Явный выход очищает оба места хранения, вспомогательные ключи и локальный режим восстановления независимо от флажка. Используется `signOut({scope: local})`: другие устройства не разлогиниваются. В SDK 2.117.1 ошибка серверного logout также очищает локальную сессию; интерфейс честно сообщает, что сервер не подтвердил выход. Получившие уведомление вкладки дополнительно удаляют свою копию `sessionStorage`, чтобы reload не восстановил её.

Перед явным выходом очередь учебных изменений отправляется. Если сохранение ещё идёт либо сеть не позволяет отправить очередь, выход останавливается с короткой ошибкой; данные остаются, можно повторить. Успешный выход не удаляет серверную историю, локальные заметки и черновики курса. При истечении сессии очередь остаётся под ID прежнего владельца, доступна для отправки после повторного входа этим пользователем и не отправляется от имени другого. Текущий web outbox по-прежнему хранится в `sessionStorage`, поэтому при несинхронизированных данных нельзя считать закрытие вкладки безопасной заменой выходу.

## Что остаётся проверить на выделенном стенде

Нет предоставленных тестовых учётных записей/почтового ящика и отдельного Supabase Auth стенда. Поэтому **не подтверждены** реальная доставка писем, действующие шаблоны recovery, allow-list возвратных URL, фактические серверные сроки/одноразовость кодов и ссылок, текущие дополнительные требования к паролям, реальные MFA/SSO и серверные правила ограничения числа сессий. Синтетические сценарии проверяют обработку ответов приложением, а не эти настройки сервера. Рабочие аккаунты и конфигурация ради теста не менялись.

Перед релизом пройти эти сценарии на отдельном стенде с реальными письмами и тестовыми ролями, включая учителя/администратора. Для локального recovery redirect адрес `http://127.0.0.1:8105/` должен быть разрешён на стенде; рабочая allow-list не менялась. Для нативного recovery нужны разрешённый `espada://auth/recovery` и установленное приложение. Также требуется физическая проверка iOS/Android: клавиатура, AutoFill/менеджер паролей, SecureStore после перезапуска, deep link и цикл фон/активность. Safari/Firefox и расширения менеджеров паролей отдельно не проверялись.
